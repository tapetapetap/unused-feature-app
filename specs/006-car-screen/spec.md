# Feature Specification: 안 써본 기능 6차 — 차 화면 개선

**Feature Branch**: `006-car-screen` (git 브랜치는 `car-unused`, 되돌리기 태그 `backup/before-car-unused` = main 74f28fa)

**Created**: 2026-11-13

**Status**: Draft

**Input**: 2026-11-13 impeccable 점검(critique 28/40, audit 14/20)에서 나온 P1·P2 문제를 모두 고친다(사용자 결정 "P1 + P2 전부"). 설계는 `docs/superpowers/specs/2026-11-13-car-screen-design.md`의 공통 C1~C5와 U1~U5다. 같은 날 같은편·DRIVE DNA도 같은 설계로 고친다.

**무엇이 바뀌나**
- 화면 글자와 누르는 칸이 폰 크기라, 차 화면 거리(팔 길이 이상)에서 읽고 누르기 어렵다. 이것을 차 기준으로 키운다.
- 회색 안내 글자와 연한 바탕 위 초록·파랑 글자가 흐리다. 낮·밤 모두 또렷하게 한다.
- 시스템 뒤로 버튼과 낮·밤 전환에서 보던 칸을 잃는다. 이것을 막는다.
- 서로 어긋나는 문구와 숫자를 맞춘다.
- 기능(무엇을 언제 알려 주는지), 음성 문장, 기록 형식은 바뀌지 않는다.

**점검과 범위**
- impeccable은 화면 디자인 점검 도구(Claude 스킬)다. critique는 사용성 휴리스틱 10개를 40점 만점으로, audit는 접근성·성능·테마·플랫폼 규칙·적응성을 20점 만점으로 매기고, 문제마다 P1(먼저)~P3 등급을 붙인다. audit의 A4·A5는 그 보고서의 문제 번호다.
- 같은편(픽업 앱)과 DRIVE DNA(운전 성향 앱)는 같은 팀이 만든 다른 앱이다. 브랜치와 GitHub 저장소가 따로이고, 화면 도우미(`Ui`)는 앱마다 따로 복사되어 있다. 이 명세는 안 써본 기능만 바꾼다. 세 앱은 같은 기준값을 쓴다.

| 점검 항목 | 등급 | 이 명세 |
|---|---|---|
| 글자가 폰 크기(small 22sp, chip 20sp, 차 지도 이름표 18~20sp) | P1 | US1, FR-001·002 |
| 누르는 칸이 작음(추천 기록 154×51dp, 닫기 99×46dp) | P1 | US1, FR-003·004 |
| 각주 대비 3.2:1(밤 3.3:1), 연한 바탕 위 초록·파랑 글자 | P1 | US2, FR-005 |
| 뒤로 버튼이 칸을 닫지 않고 앱을 나감(audit A4) | P2 | US3, FR-006 |
| 낮·밤 전환 때 열린 칸이 닫힘(audit A5) | P2 | US3, FR-007 |
| 주행 중 "한 번 알려" vs "두 번까지" | P2 | US4, FR-008 |
| 앞유리 김서림 근거 카드의 제목·숫자·막대·이유 어긋남 | P2 | US4, FR-009·010 |
| 기능 없는 구역 "전조등 0/0" | P2 | US4, FR-011 |

**용어**
- 차 기준: Android for Cars 디자인 가이드의 값이다. 누르는 칸 76×76dp 이상, 이웃한 칸 사이 23dp 이상(이 명세는 24dp로 쓴다), 보조 글자 24dp 이상, 글자 대비 4.5:1 이상.
- 큰 글자 예외: 대비 3:1을 허용하는 글자는 둘뿐이다. 40sp 이상 제목, 그리고 파랑 바탕 위 흰 굵은 글자(24sp 이상 굵게: 누를 곳 그림의 누를 버튼, 첫 실행 1·2단계 번호). 흐리게 그린 비활성 요소(주행 중 흐린 차 지도, 이 차에 없는 기능의 흐린 카드)는 '쓸 수 없음'을 보이는 표현이라 대비 기준에서 뺀다(WCAG 1.4.3의 비활성 요소 예외).
- 상황 화면: 열린 칸이 없을 때 오른쪽(세로 화면은 위)에 보이는 화면이다. 상태에 따라 첫 실행, P 안내, 써 보셨네요, 권할 것 없음, 도감 완성 중 하나다. 무엇을 보일지는 우선순위를 따른다: 주행 중 > 기록 다시 보기 > 기록 목록 > 구역 카드 > 첫 실행 > 도감 완성 > P 안내 > 써 보셨네요 > 권할 것 없음(specs/002·003 data-model "화면 상태").
- 화면 글자: 화면을 이루는 글자다(제목, 본문, 칩, 버튼, 각주).
- 그림 안 글자: 차 지도, 근거 타임라인처럼 그림 안에 그려진 글자다. 차 기준 24sp의 예외로 22sp를 쓴다. 지도 이름표는 차 그림 둘레의 좁은 자리에, 타임라인 글자는 높이 196dp로 고정된 그림 안에 놓이기 때문이다. 지도 머리 진행 원 가운데 숫자("2/14", 약 20sp)는 그대로 둔다. 같은 수를 바로 옆 "n개 익힘 · m개 남음"(24sp)이 보인다.
- 칸: 정차 중 여는 구역 카드, 추천 기록 목록, 기록 다시 보기다.
- 누르는 칸: 눌러서 무언가가 일어나는 화면 요소다(버튼, 누르는 칩, 기록 카드, 구역 줄, 차 지도 구역 점).
- 근거 카드: P 안내 화면의 "이번 운전에서 · …" 카드(타임라인)다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 차에서 읽고 누를 수 있다 (Priority: P1)

운전자는 정차 중 팔 길이 떨어진 화면에서 안내와 기록을 읽고, "추천 기록"·"닫기" 같은 칸을 한 번에 누른다. 주행 중 내비 옆 칸의 권함 카드도 한눈에 읽힌다.

**Why this priority**: 점검의 첫째 P1이다. 세 앱이 같은 화면 도우미를 써서 모든 화면이 폰 크기다.

**Independent Test**: 앱을 띄워 각 화면을 열고, UI 덤프로 누르는 칸 크기를 재고, 화면 글자 크기를 확인한다.

**Acceptance Scenarios**:

1. **Given** P 안내 화면, **When** 왼쪽 위 "추천 기록 n ›"을 본다, **Then** 높이와 폭이 76dp 이상이고 글자는 24sp 이상이다.
2. **Given** 추천 기록 목록, 구역 카드, 기록 다시 보기가 열림, **When** "✕ 닫기"와 "← 추천 기록"을 본다, **Then** 각각 76×76dp 이상이다.
3. **Given** 세로(1:1 분할) 화면의 구역 목록과 추천 기록 목록, **When** 구역 줄과 기록 카드를 본다, **Then** 줄 높이가 76dp 이상이고 줄·카드 사이가 24dp 이상이다.
4. **Given** 어느 화면이든, **When** 화면 글자를 본다, **Then** 24sp보다 작은 글자가 없고 카드 제목은 28sp 이상이다.
5. **Given** 차 지도와 근거 타임라인, **When** 그림 안 글자를 본다, **Then** 이름표와 타임라인 글자는 22sp다.
6. **Given** 주행 중 내비 옆 칸의 권함 카드, **When** 누를 곳 버튼 그림을 본다, **Then** 버튼 글자는 모두 24sp(누를 버튼은 굵게)이고 그림이 칸 안에 다 들어온다.

### User Story 2 - 낮·밤 모두 또렷하다 (Priority: P1)

운전자는 낮 화면과 밤 화면 모두에서 회색 각주와 초록·파랑 상태 글자를 또렷하게 읽는다.

**Why this priority**: 점검의 둘째 P1이다. "버튼 위치는 차종마다 조금 다를 수 있어요."가 낮 3.2:1, 밤 3.3:1이다.

**Independent Test**: 바뀐 색 값으로 글자와 바탕의 대비를 계산하고, 낮·밤 캡처로 확인한다.

**Acceptance Scenarios**:

1. **Given** 낮·밤 테마, **When** 글자의 대비를 계산한다, **Then** 모두 4.5:1 이상이다(용어의 큰 글자 예외는 3:1).
2. **Given** 구역 카드, **When** "버튼 위치는 차종마다 조금 다를 수 있어요."를 본다, **Then** 보통 회색 글자(text3)다.
3. **Given** 연한 초록·파랑 바탕의 칩("써 봄 ✓", "익힘 · 날짜", "안내함 n회", "추천 기록"), **When** 글자를 본다, **Then** 진한 초록·파랑 글자(green_text, blue_text)다.

---

### User Story 3 - 보던 칸을 잃지 않는다 (Priority: P2)

운전자가 시스템 뒤로 버튼을 누르면 앱을 나가지 않고 열린 칸을 하나씩 닫는다. 해가 져서 화면이 밤으로 바뀌어도 열어 둔 칸이 그대로다.

**Why this priority**: audit P2(A4·A5)다. 지금은 뒤로 버튼이 바로 앱을 나가고, 낮·밤이 바뀌면 열어 둔 칸이 닫힌다(에뮬레이터에서 확인).

**Independent Test**: 칸을 열고 뒤로 버튼(`input keyevent 4`)을 누르거나 낮·밤을 바꾼다(`cmd uimode night yes/no`).

**Acceptance Scenarios**:

1. **Given** 기록 다시 보기, **When** 뒤로 버튼을 누른다, **Then** 추천 기록 목록으로 돌아가고 보던 스크롤 자리다.
2. **Given** 추천 기록 목록이나 구역 카드, **When** 뒤로 버튼을 누른다, **Then** 칸이 닫히고 상황 화면이다.
3. **Given** 열린 칸이 없음, **When** 뒤로 버튼을 누른다, **Then** 지금처럼 앱을 나간다.
4. **Given** 구역 카드 또는 기록 목록(스크롤 내림) 또는 다시 보기, **When** 낮·밤이 바뀐다, **Then** 같은 칸이 같은 자리에 열려 있다.
5. **Given** 열린 칸, **When** 다른 앱으로 갔다가 돌아온다, **Then** 지금처럼 상황 화면부터 보인다(그사이 운전이 있었을 수 있다).

---

### User Story 4 - 문구와 숫자가 서로 맞는다 (Priority: P2)

운전자가 보는 문장, 제목, 숫자가 서로 다른 말을 하지 않는다.

**Why this priority**: critique P2다. 주행 중 카드가 "한 번 알려 드릴게요"와 "두 번까지만"을 함께 말하고, 앞유리 김서림 근거 카드는 제목(겹친 구간)·숫자(1번)·막대(와이퍼 12분)·이유(8분)가 서로 다르며, 기능이 없는 전조등 구역이 "0/0"으로 고장처럼 보인다.

**Independent Test**: 주행 중 기다림 카드, `rain` 장면의 P 안내, 차 지도를 캡처한다.

**Acceptance Scenarios**:

1. **Given** 주행 중 권함 전, **When** 카드를 본다, **Then** "쓸 만한 기능이 생기면 짧게 알려 드릴게요."와 "한 운전에 두 번까지만 알려요"다.
2. **Given** 앞유리 김서림 제거 안내, **When** 근거 카드를 본다, **Then** 제목은 "이번 운전에서 · 비 온 구간과 내기 순환"이고 오른쪽 숫자가 없으며, 내기 순환 표시는 "내기 순환 켬"이다.
3. **Given** 막대만 또는 순간만 있는 다른 근거 카드, **When** 오른쪽 숫자를 본다, **Then** 지금처럼 "n분" 또는 "n번"이다.
4. **Given** 이 차에서 쓸 수 있는 기능이 없는 구역(에뮬레이터의 전조등), **When** 차 지도, 세로 구역 목록, 그 구역 카드를 본다, **Then** 지도 이름표는 "전조등 · 기능 없음", 세로 구역 줄은 이름 "전조등"과 오른쪽 "기능 없음", 구역 카드는 "0 / 0 익힘" 대신 "이 차에서는 쓸 수 있는 기능이 없어요"다.

---

### Edge Cases

- 세로(1:1 분할) 화면은 앱 창 폭이 약 850dp다. 커진 글자와 칸이 이 폭에서도 잘리지 않아야 한다. 누를 곳 버튼 그림은 버튼이 가장 긴 기능(앞유리 김서림 제거)으로 확인한다. 칩 격자(권할 것 없음, 써 보셨네요, 도감 완성)는 세로 화면에서 2열이다.
- 세로(1:1) 화면에서는 차 지도를 그림으로만 둔다. 이름표를 그리지 않고 구역 점을 누르지 않는다. 구역 카드는 바로 옆 구역 목록(76dp 줄)으로 연다(사용자 결정 2026-11-13: 세로 지도는 구역 점 누름 지름이 약 46dp라 차 기준을 못 맞춘다). 가로 화면에서 이름표 상자가 지도 뷰의 왼쪽이나 오른쪽 밖으로 나가면 뷰 안으로 민다(지금 코드는 왼쪽만 민다).
- 바꾸기 전에 저장된 추천 기록은 그때의 표시 글자("내기 순환")를 그대로 보인다.
- 운전이 시작되거나 새 운전 결과가 생기면 열린 칸은 지금처럼 닫힌다(낮·밤 유지보다 먼저다).
- 낮·밤이 바뀌는 동안 운전이 시작되었으면 칸을 다시 열지 않는다.
- 주행 중에는 뒤로 버튼으로 열 칸이 없다(주행 중 칸은 이미 닫혀 있다). 뒤로 버튼은 지금처럼 앱을 나간다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 화면 글자는 24sp 이상이어야 한다. 카드 제목은 28sp 이상, 본문 26sp와 제목 크기(44~60sp)는 그대로다.
- **FR-002**: 그림 안 글자는 차 지도 이름표 22sp, 근거 타임라인 22sp여야 한다(차 기준의 예외, 용어 "그림 안 글자"). 누를 곳 버튼 그림은 자리가 넉넉해 예외 없이 24sp다(누를 버튼은 굵게, PR 리뷰 반영). 차 지도 이름표는 차 지도 뷰 안에 들어와야 한다(Edge Cases의 규칙).
- **FR-003**: 누르는 칸은 높이와 폭이 76dp 이상이어야 한다: "추천 기록 n ›", "✕ 닫기"(목록·구역 카드), "← 추천 기록", 세로 구역 줄. 기록 카드와 가로 화면의 차 지도 구역 점(누름 반경 약 65dp)은 이미 76dp를 넘으므로 그대로다. 세로 화면의 구역 점은 누르지 않는다(Edge Cases).
- **FR-004**: 따로 놓인 누르는 칸끼리, 그리고 목록의 누르는 줄·카드끼리(세로 구역 줄, 추천 기록 카드) 사이는 24dp 이상이어야 한다.
- **FR-005**: 글자는 낮·밤 모두 바탕과 4.5:1 이상이어야 한다(용어의 큰 글자 예외는 3:1, 비활성 예외는 제외). 낮 보통 회색 글자는 #62656D, 연한 초록 바탕 위 초록 글자는 #017A40(밤 #00E074), 연한 파랑 바탕 위 파랑 글자는 #0050D8(밤 #6CB4FF)이다.
- **FR-006**: 시스템 뒤로 버튼은 다시 보기 → 기록 목록 → 닫힘 순서로, 구역 카드는 닫힘으로 처리하고, 열린 칸이 없을 때만 앱을 나가야 한다.
- **FR-007**: 화면이 다시 만들어지는 설정 변화(낮·밤 전환, 창 크기 변화)에서 열린 칸(구역 카드, 기록 목록, 다시 보기)과 기록 목록 스크롤 위치가 유지되어야 한다. 다른 앱으로 갔다 오면 지금처럼 닫힌다.
- **FR-008**: 주행 중 권함 전 카드의 문구는 "쓸 만한 기능이 생기면 짧게 알려 드릴게요."(기록하지 않는 운전은 지금 문구 그대로)와 "한 운전에 두 번까지만 알려요"여야 한다.
- **FR-009**: 근거 카드는 구간(막대)과 순간(표시)이 함께 있으면 오른쪽 숫자를 보이지 않아야 한다. 하나만 있으면 지금처럼 구간은 합친 분, 순간은 횟수다.
- **FR-010**: 앞유리 김서림 제거의 근거 카드 제목은 "비 온 구간과 내기 순환"이고, 새로 기록하는 내기 순환 표시 글자는 켤 때 "내기 순환 켬", 끌 때 "외기로 바꿈"이어야 한다.
- **FR-011**: 이 차에서 쓸 수 있는 기능이 없는 구역은 차 지도 이름표가 "<구역> · 기능 없음", 세로 구역 줄의 오른쪽 글이 "기능 없음", 구역 카드의 익힘 줄이 "이 차에서는 쓸 수 있는 기능이 없어요"여야 한다.
- **FR-012**: 기능 판단, 음성 문장, 저장 형식, 상황 화면 우선순위(용어)는 바뀌지 않아야 한다.

### Key Entities

- 열린 칸 상태: 열린 구역, 기록 목록 또는 다시 보는 기록 번호, 다시 보기로 가기 전 기록 목록 스크롤(listY), 지금 화면 스크롤(scrollY), 마지막으로 본 운전 수. 설정 변화 동안만 보존한다(기기에 저장하지 않는다).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: UI 덤프에서 FR-003의 누르는 칸이 모두 76×76dp 이상이고, FR-004의 줄·카드 사이가 24dp 이상이다(가로·세로 화면).
- **SC-002**: 화면 코드에 24sp보다 작은 화면 글자가 없고(그림 안 글자 22sp는 예외), 대비 계산표(research R5)의 글자·바탕 쌍이 모두 기준(4.5:1, 용어의 큰 글자 예외는 3:1) 이상이다(낮·밤).
- **SC-003**: 에뮬레이터에서 뒤로 버튼 세 경우(US3-1~3)와 낮·밤 전환 세 경우(구역 카드, 스크롤한 목록, 다시 보기)가 수용 시나리오대로다.
- **SC-004**: 캡처로 US4의 문구 네 곳이 확인된다.
- **SC-005**: impeccable critique를 다시 돌려 29점 이상(지금 28점보다 높게)이고, 글자·누르는 칸·대비 P1이 남지 않는다.
- **SC-006**: 기존 단위 테스트가 모두 통과하고, 근거 카드 숫자 규칙 테스트가 하나 더 있다. 1~5차 시연 장면이 같은 안내를 고른다.

## Assumptions

- 기준은 Android for Cars다. Pleos 글자 규칙(specs/002 contracts/ui.md §7의 보조 22·최소 18)은 이번에 24로 올린다.
- 에뮬레이터는 density 160(1dp = 1px)이다. 실차 화면도 같은 dp 기준을 쓴다고 본다.
- 40sp 이상 글자(제목)는 큰 글자라 3:1이면 된다. 이 앱의 제목은 모두 이미 4.5:1을 넘는다.
- 누를 곳 버튼 그림은 실제 버튼 모양을 보여 주는 그림이라 누르는 칸이 아니다.
- 새로 기록한 표시 글자만 바뀐다. 이전 기록은 고치지 않는다.
- 주행 중 화면(5차 권함 카드)의 배치와 규칙은 그대로이고 글자 크기만 FR-001·002를 따른다.
