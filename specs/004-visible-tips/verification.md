## 3. 리뷰

**ponytail-review(과설계)**: 줄일 것 없음. 새 View 둘(`SoundBars`, `ZoneThumb`)은 `Views.kt`에, 샘플은 디버그 소스셋 파일 둘이다. Lean already.

**/code-review(high)**: 10건.

| # | 지적 | 처리 |
|---|---|---|
| 1 | `demo.sh seed`가 수신기가 없어도 성공 문구 | 고침: `progress`의 운전 수를 확인하고 실패면 끝낸다 |
| 2 | 강조가 벽시계(기록 시각) 기준이라 시계가 바뀌면 길어지거나 없음 | 고침: 말한 때(uptime) + 10초(V1 바뀜) |
| 3 | `speak`은 반환값이 없는 비동기라 "말했다"를 보장하지 못하고, 말하지 않았어도 "방금 들은 음성" | 일부 고침: 말한 기록이 없거나 엔진이 준비되지 않았으면 제목 "안내 음성". 엔진 안쪽의 비동기 실패는 알 수 없어 README 한계에 적었다 |
| 4 | 같은 사건을 두 시계·두 조건으로 판단 | 고침(2와 함께): 둘 다 `lastSpoken` |
| 5 | `Seed`가 출시 APK에 죽은 코드 | 고침: `app/src/debug`·`app/src/testDebug`로 옮김 |
| 6 | `SeedReceiver`가 `Progress` 키를 직접 씀 | 기록: 디버그 전용이고 키는 data-model 표가 한 곳에 적는다. 출시 코드에 시연용 쓰기 함수를 두지 않으려고 그대로 둠 |
| 7 | 미니 지도 차 그림이 큰 지도와 알파 상태를 나눔 | 고침: `mutate()` |

| 9 | `Seed.learned`가 `learnedAt` 키와 중복 | 기록: 테스트가 둘이 같음을 지킨다. 화면이 쓰는 이름이라 둠 |

**보안 직접 점검(T017)**
- `SeedReceiver`: 디버그 빌드에만 있고(병합 매니페스트 확인) `android.permission.DUMP`로 보호한다. 일반 앱은 이 권한을 받을 수 없어 adb shell만 부를 수 있다.
- 저장 값: 샘플도 앱과 같은 `progress` 키와 형식이고 기기 안에만 있다. 위치·개인 정보는 없다.
- 로그: 수신기는 기록 수만 남긴다.

## 4. 남은 한계

- 자막은 앱이 음성 엔진에 넘긴 문장이다. 엔진 안에서 소리가 났는지는 알 수 없다.
- 강조는 같은 앱 실행 안에서만 정해진다. 말한 뒤 10초 안에 프로세스가 다시 뜨면 강조가 없다.

## 5. 주행 영상 다시 녹화(T019)

**녹화에서 발견**: 콜드 부팅 직후 콘솔은 한 번도 바꾸지 않은 값을 차에 보내지 않는다. 처음 녹화 때 앱 시작 로그 "신호 받은 기능"은 11개였다(시트 열선·운전대 열선·DUAL·사이드미러 열선·오토 내/외기 없음). 그래서 `heat`는 "권할 기능이 없었어요", `multi`는 다른 차례였다. `demo.sh reset`이 시트 열선·운전대 열선·DUAL을 한 번 켰다 끄게 고치자 14개가 됐고, 두 장면이 검증 기록과 같아졌다. 사이드미러 열선과 오토 내/외기는 콘솔에 조작이 없어 README 한계에 적었다. 앱 코드는 바꾸지 않았다.
