# UI Contract: 추천 기록 페이지

002 contracts(`specs/002-redesign-21-features/contracts/ui.md`)에 더하는 것만 적는다. 색과 글자 크기 규칙은 그 문서의 §7과 같다.

## 1. 지도 머리 버튼

- **글자**: 기록이 있으면 "추천 기록 {n}  ›", 없으면 "추천 기록  ›"
- **모양**: 칩. 글자 22sp, 굵기 600, 파랑 글자에 흐린 파랑 바탕이다.
- **자리**: 진행 원 옆 글자 묶음의 셋째 줄("내 차 기능", "{n}개 익힘" 아래)이다. 가로·세로 모두 같다. 세로 화면은 지도 머리 줄의 폭이 좁아서 줄 오른쪽 끝에는 들어가지 않는다(goldfish #8, 사용자 결정).
- **주행 중**: 흐리게(알파 0.4) 하고 비활성(`enabled=false`)으로 둔다. 비활성 뷰는 누르기를 받지 않고, 화면 덤프에 `enabled="false"`로 나온다.

## 2. 목록 페이지 (HISTORY)

| 자리 | 글자 |
|---|---|
| 작은 제목 | 지난 안내 |
| 큰 제목 | 추천 기록 |
| 닫기 | "✕  닫기"(구역 카드와 같은 칩) |
| 날짜 머리 | "{M}월 {d}일". 올해가 아니면 "{yyyy}년 {M}월 {d}일" |
| 항목 | 아이콘 타일, 기능 이름(30sp, 700), 시각 "{오전/오후} {h:mm}"(22sp, 흐린 글자), 이유 한 줄(24sp) |
| 써 봄 | 초록 칩 "써 봄 ✓". 익힌 기능만 붙고, 이때 아이콘 타일도 초록이다(아니면 파랑) |
| 빈 상태 큰 글 | 아직 추천받은 기능이 없어요 |
| 빈 상태 본문 | 운전이 끝나 P에 놓으면 기능 하나를 알려 드리고, 여기에 남겨요. |

항목 카드 전체가 누르는 자리다.

**조립**(승인한 설계 미리보기와 같다)
- **날짜 머리**: 안내 화면의 "방금 끝난 운전" 줄과 같은 작은 제목 모양(`small`)이다.
- **항목 카드**: 왼쪽에 아이콘 타일(96)을 둔다. 오른쪽 첫 줄에는 기능 이름, 시각, "써 봄 ✓" 칩(익힘일 때)을 차례로 둔다. 둘째 줄에는 이유 한 줄을 둔다.
  - `card(row(24, tile, column(8, row(12, 이름, 시각, 칩), body(이유, 24f)), grow = 1))`
- **빈 상태**: 다른 상황 화면처럼 큰 타일과 큰 글, 본문으로 이루어진다.
  - `hero(tile(R.drawable.ic_clock, Tile.GREY), 큰 글, 본문)`

## 3. 다시 보기 (RECORD)

- **위쪽 줄**: 칩 "←  추천 기록"을 두고, 익힘이면 초록 칩 "써 봄 ✓ {M}월 {d}일"(날짜가 없으면 "써 봄 ✓")을 함께 둔다.
- **작은 제목**: "{M}월 {d}일 {오전/오후} {h:mm} 운전 · {m}분". 올해가 아니면 날짜 앞에 "{yyyy}년"을 붙인다
- **그 아래**: 002 contracts §1·§3의 안내 화면과 같다(아이콘 타일, "다음엔 {기능}을(를) / 켜 보세요", 이유 한 줄, 근거 카드, "여기를 누르세요" 카드, 각주).
- **지도**: 그 기능의 구역에 선택 링을 그린다. 구역 카드를 열 때와 같은 굵은 바깥 원이다(data-model "선택 링"). 파란 깜빡임과 초록 반짝임은 없다.

## 4. 바뀌지 않는 것

002의 상황 화면 글자, 구역 카드, 음성 문장, 시스템 알림은 바꾸지 않는다.
