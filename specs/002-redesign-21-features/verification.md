# Verification: 안 써본 기능 2차 (2026-11-08)

환경: MacBook Pro(Apple M5 Pro), Pleos Connect Emulator v2.1.0 arm64(API 34), JDK 17, AGP 8.8.2. 디버그 빌드(앱 시계 10배). 차 신호는 Virtual Console HTTP와 `scripts/demo.sh`.

## 에뮬레이터: 신호

앱 시작 로그 "신호 받은 기능": 18개 중 16개. 지원 기능은 14개다. MAX A/C와 주행 모드는 `ERROR_NOT_SUPPORTED_PROPERTY`라 빠지고, 전조등·하이빔 스위치 선택지가 `[OFF, ON]`(AUTO 없음)이라 오토 라이트·하이빔 보조도 빠진다. 진행 원은 0/14에서 시작한다.

> 처음 검증 때는 0/16이었다. 2차 리뷰 5번(스위치에 AUTO가 없으면 지원 안 함)을 넣은 뒤 다시 확인하지 않아, goldfish 리뷰 날 화면에서 0/14를 보고 찾았다. `docs/screenshots/`는 그 전에 찍어 분모가 16이다.

## 확인하지 못한 것

- **MAX A/C, 주행 모드**: 이 에뮬레이터에 없다. 판단은 테스트로만.
- **오토 라이트·하이빔 보조**: 이 에뮬레이터는 스위치 선택지에 AUTO가 없어 지원 안 함이다. 안내도 나오지 않는다.
- **사이드미러 열선·오토 내/외기·뒷좌석 시트 열선·앰비언트의 "사용"**: 콘솔이 값을 SDK에 전달하지 않거나(앰비언트 스위치는 늘 OFF) 콘솔에 항목이 없다. 안내까지는 시연된다.
- **실제 차의 세로 화면 크기, 주행거리 갱신 주기, 표시등 정책**: 차에서만 알 수 있다.
- **부팅 시 자동 시작**: 2차에서 바꾸지 않았다(1차 검증에서 확인).

## 확인한 플랫폼 사실 (다음 작업에 쓸 것)

- 계기판 표시등은 `getTelltalesInfo`도 구현상 `PRIVATE_CAR_SAFETY`가 필요하다(인터페이스 표기는 `CAR_SAFETY`). 외부 앱은 쓸 수 없다.
- 비DO 앱은 기어 D에서 정지 중이어도 Pleos가 가린다.
- Virtual Console은 주행거리가 줄어드는 쓰기를 무시한다. 새 세션의 첫 쓰기는 이전 값을 다시 내보낸다.
- 에뮬레이터 SDK는 뒷좌석 착좌를 늘 true로 보낸다(콘솔 값과 무관). 그래서 시트 열선을 켠 운전에서 뒷좌석 시트 열선이 후보가 된다.
- `wm size`로 화면을 세로로 바꿔도 Pleos가 앱 창을 다시 배치하지 않는다. `am task resize <id> 853 90 1653 1300`으로 앱 창만 세로 비율로 만들면 `layout-port`가 적용된다.
- 디버그 빌드의 시계 10배는 `ApplicationInfo.FLAG_DEBUGGABLE`로 정한다.
- 전조등·하이빔 스위치 선택지(`check…LightSwitchCapabilities`)는 둘 다 `[OFF, ON]`이다. 콘솔 전조등 "Auto"가 SDK 스위치에 나타나지 않는 것과 맞는다.
- 비DO 앱은 D뿐 아니라 N에서도 Pleos가 가리고, R에서는 후방 카메라가 화면을 덮는다. 가려진 앱의 글자는 `uiautomator dump`로 읽힌다.
- 스크립트를 멈춘 상태에서도 콘솔에 클라이언트가 1개 붙어 있었다(`/browser/session`의 `clients`=1, 로컬 하트비트 없음. 브라우저에 열린 콘솔 페이지로 보인다). 이때 스크립트의 첫 쓰기마다 콘솔의 앞·뒤 제상이 켜졌고, 앱은 그 둘을 바로 "익힘"(정차 중)으로 기록했다. 시연 전에 콘솔 페이지를 닫는다.

## 리뷰 반영

**1차 ponytail-review** (과설계): 4건 반영.
- `hero()`의 쓰지 않는 글자 크기 매개변수 삭제
- `super`만 부르는 `performClick()` 재정의 삭제
- 한 번 쓰는 `labelRows` 필드를 인라인
- 흰 글자를 덮어쓰던 3곳과 `Tile.white` 분기를 `on_accent` 색 리소스와 `Tile(from, to, fg)`로 정리

**2차 /code-review high** (정확성): 10건 모두 반영.

| # | 지적 | 조치 |
|---|---|---|
| 1 | 구역 카드를 연 채 운전하면 P 뒤에도 카드가 안내를 가림 | 운전 중이거나 운전 횟수가 바뀌면 열린 구역을 닫음. 에뮬레이터로 확인 |
| 2 | 구독 호출이 동기 예외를 던지면 서비스가 죽음 | 구역별 `watch*`를 각각 try/catch, 하나가 실패해도 나머지는 계속 |

**goldfish 리뷰**(구현 뒤 실행): 지적 25개 중 15개 수정(사용자 결정 2개 포함), 10개 기록. `goldfish-review.md`.

**goldfish 리뷰 날 찾아 고친 것**
- 진행 원 0/14 확인 중, 지원 안 하는 기능이 안내 후보에서는 빠지지 않는 것을 찾았다. 2차 리뷰 5번은 분모에만 적용되어 있었다. `Coach.finish`에 `unsupported`를 넘기고 테스트를 추가했다.
- 연결 실패 알림 줄을 계약 문구로 바꾸고, 넣는 쪽과 지우는 쪽이 같은 상수를 쓰게 했다.
- 주행 중 화면 기준을 "기록 중인 운전"에서 "기어 ≠ P"로 바꾸고, 기록하지 않는 운전의 아랫줄을 따로 두었다(사용자 결정).

**위 변경의 리뷰**: ponytail-review는 지적 없음. /code-review high는 10건이었고, 7건을 반영하고 3건은 보류했다.
- 반영:
  - 기록하지 않는 운전 중에 처음 쓴 기능의 메모가 "정차 중"으로 남음 → "운전 중"으로 남김(에뮬레이터로 확인)
  - 연결 실패가 계속되면 10초마다 화면을 다시 그려 스크롤이 맨 위로 감 → 띠가 새로 생길 때만 다시 그림
  - 연결은 됐는데 신호가 하나도 안 오면 "다시 연결해요" 띠가 남음 → 초기화 성공 때 지움
  - 지원 안 하는 기능이 지난 안내로 남아 있으면 안내 화면이 뜸 → 안내 화면은 지원 기능일 때만
  - 서비스가 멈출 때 화면에 알리지 않음 → 알림
  - 운전 끝의 `driving`·`recording` 정리가 두 군데에 있음 → `onChange` 한 곳으로
  - `notParked` 표현을 정리함
- 보류:
  - `driving`·`recording`을 getter로 바꾸기, `Tracker.driving` 이름 바꾸기, 알림 줄 집합을 Boolean으로 바꾸기
  - 동작은 맞고 여러 파일을 건드리는 정리라서 마감 전에는 하지 않았다.
- 남은 한계: 운전 도중 시작 직후에는 지원 기능 확인이 끝나기 전에 주행 중 화면이 고정된다. 그래서 지도 머리 숫자가 P까지 18개 기준으로 남는다. 이 화면은 Pleos가 가려 보이지 않는다.

**검증 중 찾아 고친 것**
- 표시등 권한 문제로 기능 3개 제외(설계 문서 "구현 중 바뀐 것").
- 콘솔에 남은 상태 때문에 시연 결과가 매번 달라짐 → `demo.sh reset`.
- 1분 안의 근거가 모두 "0분" → 초 단위 표시.
- 좁은 가로 창에서 상황 화면이 0폭 → 지도 칸 3:5 비율.
- 앰비언트 스위치 읽기를 넣었다가, SDK가 콘솔 값을 반영하지 않아 효과를 확인할 수 없어 다시 뺐다.
- `demo.sh`의 한 줄 반복문 안 `#` 주석이 뒤를 잘라 문법 오류 → 주석을 줄 밖으로.
- 콘솔이 줄어드는 주행거리를 무시해 두 번째 `highway`부터 고속 구간이 0 → 지금 주행거리에서부터 늘림.
