- 다른 세 장면의 까닭은 하나다. 이 에뮬레이터는 조수석 착좌가 반대로 와서(콘솔 false = 앉음) 장면이 온도를 바꾸면 동승석 개별 온도도 기회가 된다. 4차에서는 기능 표 순서에 밀려 보이지 않았다. 5차는 권함도 안내 횟수를 세므로, P는 횟수가 적은 동승석 개별 온도를 고른다. 규칙(FR-006, FR-012)대로이고 코드 리뷰에서도 설계로 유지한 항목이다. spec 표만 결과대로 고쳤다.
- `multi`의 권함이 표 예상(동승석 개별 온도)과 달리 운전대 열선인 것도 기능 표 순서 때문이다(운전대 열선이 앞).

## 6. 남은 한계

- 주행 판단은 기어(P가 아니면 주행)다. 실차에서 Pleos 주행 제한 상태와 기어가 어긋나는 때가 있을 수 있다.
- 분할은 에뮬레이터 1:1만 봤다. 실차 비율(문서상 2:1)에서 카드 크기는 보지 못했다.
- 공조 신호를 앱 시작 때 못 받는 실행이 있다(에뮬레이터 콘솔). 시연 전 "신호 받은 기능" 로그를 단어 단위로 확인한다.
- 분할 화면에서는 `uiautomator dump`가 이 앱 창을 잡지 못해 화면 확인을 캡처로 했다.
- US1-3은 부분 확인이다(3절).
- 실차 앱 마켓 심사가 주행 최적화 선언과 주행 중 음성 권함을 허용하는지는 알 수 없다(approval-gate "예측할 수 없는 것").
