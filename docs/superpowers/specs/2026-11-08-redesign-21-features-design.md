# 안 써본 기능 2차 — 화면 새로 짜기 + 권할 기능 21개 (brainstorming)

- 작성일: 2026-11-08
- 앞 설계: `2026-11-08-unused-feature-design.md` (1차, 기능 6개, 글자만 있는 화면)
- 진행 방식: 사용자와 질문·시안을 주고받으며 정함(시안 도구: superpowers visual companion). 기능 목록 확정 뒤 "시안 안 봐도 되니 정한 것으로 개발" 지시.
- 구현 중 변경: 기능 21개 → 18개 등. 맨 아래 "구현 중 바뀐 것".
- 시안: `docs/design/mockup-layout.png`(배치), `docs/design/mockup-states.png`(상황별 8화면). 같은 이름의 `.html`은 원본.

## 왜 다시 짜나

1. 시연을 본 사용자가 "무엇이 바뀌는지 안 보인다", 화면이 투박하다고 지적했다. 원인: 61초 동안 앱 화면이 그대로이고, 풍량 변화는 에뮬레이터 화면 어디에도 안 보이며, 안내 카드는 글자만 바뀐다.
2. 권할 기능이 6개뿐이라 몇 번 운전하면 할 말이 없다. 사용자가 "권할 기능을 최대한 많이 확보"하라고 했다.

- 사용 신호를 한 번도 받지 못한 기능(그 차에 없는 기능)은 권하지 않는다(1차 규칙 유지). 그런 기능은 진행 원의 분모에서도 뺀다.

## 화면

시안 그대로 구현한다. 가로 1680×1210(에뮬레이터 앱 창) 기준, 세로는 `layout-port`.

1. **첫 실행**: 진행 원 0/n, 지도 회색, 세 단계 설명.
2. **주행 중**: "운전 중이에요" 큰 글자 + "차를 세우고 P에 놓으면 알려 드릴게요." 지도는 흐리게. 화면은 운전이 끝날 때까지 바뀌지 않는다(원칙 I). 실제 차가 움직이면 Pleos가 이 화면을 가릴 수 있다(앱은 DO 아님).
3. **운전 직후 안내**: 기능 아이콘 타일 + "다음엔 ○○를 켜 보세요" + 이유 한 줄, 근거 타임라인, 누를 곳 그림. 지도에서 해당 구역 점이 파랗게 깜빡인다.
4. **써 보셨네요**: 초록 타일과 체크, 도감 칸(진행 막대), 처음 쓴 순간. 새 안내와 같이 오면 안내 화면 위에 초록 띠.
5. **권할 것 없음**: 이번 운전에서 쓴 기능 칩, 남은 기능 칩.
6. **도감 완성**: 진행 원 n/n, 기능별 익힌 날짜, "○월 ○일부터 운전 ○번 만이에요."
7. **구역 카드**: 지도의 구역 점(세로는 구역 목록)을 누르면 오른쪽에 그 구역 기능들의 카드(상태, 언제 쓰면 좋은지, 누를 곳). 정차 중에만 누를 수 있다.
8. **다크 테마**: 같은 화면을 Pleos 다크 토큰으로.

알림 줄: 연결 실패(빨강 계열), 그 차에 없는 기능 안내(회색).

## 오류 처리

- 1차와 같음: 구독 실패한 신호는 없는 것으로 보고 그 신호에 기대는 기능은 권하지 않는다.
- 표시등·와이퍼 스위치 읽기 실패는 기록만 하고 다음 주기에 다시 읽는다.
- 주행거리 신호가 없으면 크루즈는 1차 조건(20분 운전)으로 돌아가고, LFA·주행 모드는 권하지 않는다.

## 테스트

- 21개 기능마다 "기회 있음/없음"과 "썼음"을 JUnit으로 확인(원칙 IV).
- 시각 기반 판단(정차 길이, 비 구간, 밤 구간, 고속 구간, 수동 변경 횟수)은 가짜 시계로 확인.
- 근거 기록의 저장·복원(문자열 변환) 확인.
- 에뮬레이터: 시연 가능한 14개 중 대표 시나리오를 `scripts/demo.sh`에 추가해 확인하고 화면을 캡처.

|---|---|---|
| 기능 21개 → **18개**. 오토 홀드, 차로 유지 보조(LFA), i-PEDAL을 뺌 | 세 기능은 계기판 표시등으로만 "썼는지" 알 수 있는데, SDK 구현(`SafetyImpl`)이 표시등 **읽기**(`getTelltalesInfo`)에도 `PRIVATE_CAR_SAFETY`(보호 수준 internal\|role, 외부 앱은 받을 수 없음)를 요구한다. 인터페이스 표기는 `CAR_SAFETY`였지만 실제 구현이 다르다. 확인할 수 없는 기능은 권하지 않는다(원칙 II) | 에뮬레이터 `SecurityException: getTelltalesInfo need Permission`, `javap -v SafetyImpl`, `pm list permissions -f` |
| `CAR_SAFETY` 권한과 브레이크 신호 구독을 뺌 | 위 세 기능에만 쓰였다(헌법: 쓰는 조회 권한만 선언) | — |
| 하이빔 보조는 남김 | 하이빔 스위치(`getHighBeamLightSwitch` = AUTOMATIC, `CAR_LIGHTS`)로 확인할 수 있다 | 에뮬레이터에서 신호 수신 확인 |
| 주행 중 화면 | 기어가 D면 속도 0이어도 Pleos가 앱 위에 "주행 중에는 사용할 수 없습니다"를 덮는다(앱이 DO가 아니라서). 앱의 "운전 중이에요" 화면은 그 아래에 고정 | `docs/screenshots/02-driving-blocked-by-pleos.png` |
| 근거 시각 | 1분 미만은 "40초"처럼 초로 | 시연(시계 10배)에서 조작이 첫 1분 안에 몰려 전부 "0분"으로 보였다 |
| 지도 칸 | 고정 600dp → 가로 3:5 비율 | 창이 좁아지면 상황 화면이 0폭이 되는 것을 세로 확인 중 발견 |
| 사이드미러 이름표 | 점 아래 → 위 | 아래에 두면 운전대 이름표와 겹친다 |
| 에뮬레이터 지원 | 18개 중 16개 신호 수신. MAX A/C·주행 모드는 이 에뮬레이터에 없어(ERROR_NOT_SUPPORTED_PROPERTY) 진행 원 분모에서 빠짐(0/16). 콘솔로 "사용"까지 만들 수 있는 기능은 10개 | 앱 로그 "신호 받은 기능", 정차 중 사용 확인 |
| 스위치 읽기 | 전조등·하이빔 스위치도 와이퍼처럼 주행 중 3초마다 읽음 | 2차 리뷰: 램프 변화 없이 스위치만 AUTO로 바꾸면 알아채지 못했다 |
| 시연 스크립트 | `reset` 추가, `highway`는 지금 주행거리에서부터 늘림 | 콘솔은 줄어드는 주행거리 쓰기를 무시한다(검증 중 발견) |
