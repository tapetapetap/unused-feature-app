# 설계: 추천 기록 페이지 (2026-11-09)

## 목적

지난 안내를 나중에 다시 볼 수 있게 한다. 지금은 마지막 운전의 안내 1개(`last_pick`, `last_reason`, `last_marks`)만 저장하므로, 다음 안내가 나오면 앞의 안내가 사라진다. 구역 카드는 기능별 "안내함 n회" 횟수만 보여 준다.

사용자 요청: "추천받은 기록을 나중에 다른 페이지에서 확인할 수 있도록 하는 기능이 있어? 없으면 추가해서 구현해줘"

## 사용자가 정한 것

- **범위**: "목록 + 다시 보기". 목록을 보여 주고, 항목을 누르면 그때 안내 화면(근거 타임라인 + 누를 곳)을 다시 본다.
  - 고르지 않은 안: "목록만", "운전 일지(권할 것 없던 운전과 확인까지 모두)"
- **방식**: 구역 카드처럼 같은 화면 안에서 오른쪽 상황 칸을 기록 페이지로 바꾼다(방식 A).
  - 고르지 않은 안: 별도 Activity(방식 B). 시스템 뒤로가기는 자연스럽지만, 지도·테마·주행 중 처리를 따로 만들어야 하고 구역 카드와 방식이 달라진다.

## 사용자가 보는 것

- **들어가는 곳**: 지도 머리("내 차 기능" 오른쪽)에 "추천 기록 n" 버튼(n = 기록 수, 0이면 숫자를 빼고 "추천 기록").
  - 정차 중에만 누를 수 있다. 주행 중에는 지도처럼 흐리게 하고 누르기를 막는다.
  - 가로·세로 모두 지도 머리에 있다.
- **목록 페이지** (오른쪽 상황 칸):
  - 맨 위에 "추천 기록" 제목과 "✕ 닫기"(구역 카드와 같은 모양)를 둔다.
  - 기록을 날짜별로 묶고 최신을 위에 둔다. 날짜 머리는 "11월 9일"이다.
  - 항목은 기능 아이콘, 기능 이름, 시각("오후 7:50"), 이유 한 줄로 이루어진다. 그 기능을 익혔으면 "써 봄 ✓"을 붙인다.
  - 기록이 없으면 "아직 추천받은 기능이 없어요"와 "운전이 끝나 P에 놓으면 기능 하나를 알려 드리고, 여기에 남겨요."를 보여 준다.
- **다시 보기 페이지** (항목을 누르면):
  - 맨 위에 "← 추천 기록"(목록으로 돌아감)을 둔다.
  - 그 아래는 그때의 안내 화면과 같다.
    - 작은 제목은 "11월 9일 오후 7:50 운전 · 2분"이다.
    - 그 아래로 기능 아이콘 타일, "다음엔 ○○를 켜 보세요", 이유 한 줄, 근거 타임라인 카드, "여기를 누르세요" 카드가 이어진다.
  - 그 기능을 익혔으면 아이콘 타일 위에 초록 칩 "써 봄 ✓ {월}월 {일}일"을 둔다.
  - 지도에는 그 기능의 구역을 선택 링으로 표시한다. 파란 깜빡임은 "이번 안내"를 뜻하므로 쓰지 않는다.
- **닫히는 때**: 기어가 P에서 벗어나 운전이 시작되면 기록 페이지(목록·다시 보기)는 닫히고 주행 중 화면이 된다. 운전 끝 뒤에는 상황 화면(안내·확인 등)이 나온다. 구역 카드와 같은 규칙이다.
- **구역 카드와의 관계**: 둘은 동시에 열리지 않는다. 기록을 열면 구역 카드가 닫히고, 구역을 누르면 기록 페이지가 닫힌다.

## 데이터

- **기록 1개**: 안내가 나간 운전 끝마다 남긴다. `Progress.record(outcome)`에서 `outcome.pick`이 있을 때 추가한다. 권할 것이 없던 운전은 남기지 않는다.

  | 필드 | 값 |
  |---|---|
  | `at` | 운전 끝 시각(벽시계 ms) |
  | `pick` | 기능 이름(`Feature.name`) |
  | `reason` | 이유 한 줄(`outcome.reason`) |
  | `driveMs` | 운전 길이(`outcome.driveMillis`) |
  | `marks` | 그 기능의 근거(`outcome.marks`, 최대 60개) |

- **저장**: SharedPreferences "progress"의 키 `history` 하나에 문자열로 저장한다.
  - 기록끼리는 `\u001E`, 필드끼리는 `\u001F`로 나눈다.
  - `marks` 필드는 기존 `Marks.encode`(줄마다 `kind|at|end|text`)를 그대로 쓴다.
  - 화면 글자에는 이 제어 문자가 나오지 않는다.
- **크기**: 같은 기능은 최대 3번까지만 권하므로 기록은 최대 18 × 3 = 54개다. 지우는 규칙을 두지 않는다.
- **읽기 오류**: 필드 수가 맞지 않거나, 기능 이름을 모르거나(빠진 기능), 숫자를 읽을 수 없는 기록은 건너뛴다. 나머지 기록은 보여 준다.
- **"써 봄"**: 그 기능이 지금 익힘이면 붙인다. 익힌 기능은 다시 권하지 않으므로, 익힘이면 안내 뒤에 쓴 것이다. 날짜는 `learned_at_<id>`다.
- **이전 기록**: 이번 버전 전에 나간 안내는 시각이 저장되어 있지 않아 옮기지 않는다. 기존 `last_*` 키는 지금 상황 화면용으로 그대로 둔다.

## 구조

| 파일 | 바꾸는 것 |
|---|---|
| `Coach.kt` | `data class Record(at, pick, reason, driveMs, marks)`와 `object History { encode, decode }`(`Marks` 옆, 순수 Kotlin) |
| `Progress.kt` | `record()`에서 `pick`이 있으면 `history`에 기록을 덧붙임, `history(): List<Record>`(최신이 앞) |
| `Screens.kt` | `history(records, learned, learnedAt, onOpen, onClose)` 목록 페이지. `tip()`은 작은 제목과 위쪽 줄(돌아가기·써 봄 칩)을 바깥에서 줄 수 있게 매개변수를 더한다(기본값은 지금과 같음) |
| `MainActivity.kt` | 상태 `HISTORY`(목록)와 `RECORD`(다시 보기), 열린 기록 번호. 우선순위는 DRIVING > RECORD > HISTORY > ZONE > … 운전 시작·운전 횟수 변화 때 닫는다(`openZone`과 같은 자리) |
| `res/layout/map_head.xml` | "추천 기록" 버튼(글자 + 갈매기 기호), MainActivity에서 숫자·누르기·주행 중 흐림을 설정 |

## 확인

- **단위 테스트**(`CoachTest`, 원칙 IV):
  - `History.encode/decode` 왕복(근거 여러 개, 근거 없음, 한글·기호가 든 이유)
  - 망가진 기록 건너뛰기
- **에뮬레이터**:
  1. `reset` → 지도 머리 "추천 기록" → 빈 페이지
  2. `climate` → `wiper` → 기록 2개(오토 와이퍼가 위), 각각 이유 한 줄
  3. 공조 AUTO 항목 누르기 → 그때 근거 3개와 AUTO 강조, 지도 공조 패널 선택 링
  4. `learn` 뒤 공조 AUTO 항목에 "써 봄 ✓"
  5. 기록 페이지를 연 채 기어 N → 주행 중 화면(UI 덤프) → P → 상황 화면
  6. 다크·세로에서 잘림 없음

## 범위 밖

- 기록 지우기, 검색·필터, 권할 것 없던 운전 기록(운전 일지)
- 시스템 뒤로가기로 닫기. 구역 카드도 지원하지 않는다. 화면 안의 "✕ 닫기"와 "← 추천 기록"으로 닫는다.
- 이번 버전 이전 안내를 기록으로 옮기기
