- 날짜: 2026-11-11 새벽
- 출처: 사용자 메시지(11/11)는 같은편을 고도화하면서 "나머지 두 앱도 같은 내용은 아니어도 비슷하게 고도화할 부분을 찾아 진행"하라고 했다. 사용자는 자는 중이고 승인 없이 진행하라고 했다. 그래서 근거를 대고 정했다.
- 바탕: specs 001~003(1차, 21개 기능 재설계, 추천 기록). main 3b723b4.

## 같은편 요청을 첫 앱으로 옮기기

| 같은편 요청 | 첫 앱에서 | 결정 |
|---|---|---|
| 만날 곳 카드 안 지도 | 추천 기록 카드는 아이콘과 글자뿐이다. 그 기능이 차 어디에 있는지 목록에서 보이지 않는다 | D2 기록 카드 미니 지도 |
| 통화·마이크가 켜졌는지 알기 어려움 | P에서 음성으로 말한 문장이 화면에 없다. 추천 구역 점 깜빡임이 작다 | D1 음성 자막, D3 처음 10초 강조 |
| 데리러 갈 사람 다섯 명 | 시연을 처음 시작하면 추천 기록·도감이 비어 있다 | D4 샘플 기록 |
| 여러 명 함께 | 이 앱은 "운전마다 딱 한 가지"가 원칙이다(1차 헌법·첫 실행 화면) | 옮기지 않는다 |

## 결정

### D1. 음성 자막

- 안내(P)에서 말한 문장(`Feature.speech`)을 안내 화면 첫 카드 아래에 스피커 아이콘과 함께 보인다.
  - 말한 뒤 6초 동안 아이콘 옆 소리 막대 세 개가 움직인다.
  - 다시 보기(추천 기록)에서도 "그때 들은 음성"으로 같은 문장을 보인다. 막대는 움직이지 않는다.
- 확인 화면("써 보셨네요")과 권할 것 없음은 말하지 않으므로 자막이 없다(앱 규칙).

### D2. 추천 기록 카드 미니 지도

- 기록 카드 오른쪽에 작은 차 지도(위에서 본 차 그림)를 둔다. 그 기능의 구역에 파란 점과 링을 그리고, 써 본 기능이면 초록이다.
- 차 지도 그림(`car_top`)과 구역 좌표(`Zone.x·y`)는 이미 있다. 새 View는 이름표 없이 그림과 점 하나만 그린다.
- 버린 안: 큰 차 지도(`CarMapView`)를 줄여 쓰기. 이름표와 진행 원이 작은 크기에서 겹친다.

### D3. 추천 구역을 처음 10초 강조

- 새 안내가 뜬 뒤 10초 동안 아래처럼 강조한다. 그 뒤로는 지금의 작은 맥박이다.
  - 차 지도의 추천 구역: 지금 맥박보다 두 배 넓은 링이 1.2초마다 퍼지고, 구역 이름표를 굵게 한다.
  - "여기를 누르세요" 카드의 버튼은 1~3차부터 이미 파랗게 깜빡인다(`Ui.where`의 `pulse`). 그래서 손대지 않는다.
- 움직임 줄이기 설정이면 효과 없이 굵은 테두리만 둔다.

### D4. 시연 데이터

- 디버그 빌드 전용 수신기 `SeedReceiver`가 샘플 상태를 넣는다.
  - 추천 기록 6개(최근 3일, 서로 다른 기능, 근거 한두 개)
  - 익힘 2개(그중 하나는 기록에 있는 기능 → "써 봄 ✓")
  - 운전 6번, 첫 운전 3일 전
- 기록 저장 형식은 앱의 `History.encode`를 그대로 쓴다. 제어 문자가 들어가 XML 파일로 직접 만들면 틀리기 쉽기 때문이다.
- `scripts/demo.sh seed`가 수신기를 부르고 앱을 다시 연다.

## 범위 밖

- 한 운전에 여러 기능 안내(원칙)
- 음성 다시 듣기 버튼(요청에 없고, 다시 확인하는 일은 자막으로 충분하다. YAGNI)

## 검증 기준(초안)

- 1~3차 단위 테스트(`CoachTest` 45개)가 그대로 통과한다.
- 새 단위 테스트
  - 샘플 기록이 `History.decode`로 6개 읽히고, 익힘 2개다(순수 함수 `Seed.records()`).
  - 자막 판단: 안내 화면에만 있고, 확인·권할 것 없음에는 없다.
- 에뮬레이터
  - `climate` 뒤 안내 화면에 자막과 소리 막대, 차 지도 강조 링
  - `seed` 뒤 추천 기록 6줄에 미니 지도
