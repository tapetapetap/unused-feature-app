# 안 써본 기능 — 설계 초안 (brainstorming)

- 작성일: 2026-11-08
- 근거 자료: `../아이디어 발산 2 - 빈 칸 지도와 상위 3개.md` 3회차 G 갈래 "안 써본 기능"(21점)
- 진행 방식: 사용자가 자는 동안 승인 없이 끝까지 진행하라고 위임했습니다(2026-11-08). brainstorming의 질문 단계는 아래 "결정 기록"에 근거를 대고 직접 정했습니다. 사용자는 아침에 이 기록을 보고 뒤집을 수 있습니다.

## 한 줄

운전이 끝나 P에 놓으면, **이번 운전에서 쓸 기회가 있었는데 쓰지 않은 차 기능 하나**를 음성과 카드로 알려 줍니다. 나중에 그 기능을 실제로 쓰면 차 신호로 확인하고 "익힘"으로 표시해 다시 알리지 않습니다.

## 문제와 차별점

- 새 차 첫 90일 동안 첨단 기능 셋 중 하나 이상이 한 번도 쓰이지 않는다는 J.D. Power 통계가 있습니다. 출고 설명은 한꺼번에 듣고 잊습니다.
- 가장 가까운 경쟁작 "내 차 튜토리얼"(SYNC-Dongihwa/pleos-app)은 처음에 기능을 순서대로 가르칩니다.
- 이 앱은 **상황이 실제로 왔는데 조작이 없었다**는 사실, 곧 "조작이 없음"을 신호로 씁니다. 가르치는 시점은 그 상황을 겪은 직후 한 번, 하나뿐입니다.

## 결정 기록 (질문 대신 근거로 정함)

| 질문 | 결정 | 근거 |
|---|---|---|
| 언제 알려 주나 | 주행 기어(D·R 등)에서 P로 바뀌고, 그 주행이 1분 이상이었을 때 | 주행 중 화면·음성 안내는 주의분산 심사 대상. 1분 미만은 주차 위치 조정이라 운전으로 보지 않음 |
| 몇 개 알려 주나 | 한 번에 하나 | 원 아이디어의 핵심("다음 정차 때 하나만"). 여러 개면 출고 설명과 똑같아짐 |
| 어떻게 알려 주나 | Pleos TTS(ON_DEVICE) 한 문장 + 알림 + 앱 카드 | 운전자는 화면을 안 볼 수 있음. TTS가 실패해도 알림과 카드는 남음. Pleos SDK 활용도(심사 "기술 활용성") |
| 같은 기능을 몇 번까지 | 같은 기능은 최대 3번. 그 뒤엔 "관심 없음"으로 보고 멈춤 | 잔소리가 되면 앱을 끔 |
| 무엇을 "익힘"으로 보나 | 해당 기능의 사용 신호가 한 번이라도 오면(알려 준 적 없어도) | 이미 아는 기능을 알려 주면 신뢰를 잃음 |
| 후보가 여럿이면 | 알려 준 횟수가 가장 적은 것, 같으면 표의 순서 | 새로운 걸 먼저. 표 순서는 체감이 큰 순 |
| 앱이 꺼져 있어도 감지하나 | 포그라운드 서비스가 주행을 지켜봄. 부팅 시 자동 시작 | "매 운전 이후"를 사용자가 앱을 열지 않아도 지켜야 함 |
| 화면 기술 | 일반 Activity + XML View | Pleos 문서가 일반 Activity를 전제로 함. 화면이 카드 하나와 목록 하나라 Compose 의존성이 필요 없음 |
| 저장 | SharedPreferences | 저장할 것이 기능별 횟수와 익힘 여부뿐 |
| 서버·계정 | 없음. 기록은 차 안에만 | 개인정보 동의 범위를 최소화. 공모전 범위 |

## 다루는 기능 (첫 버전 6개)

모두 Pleos Vehicle SDK 2.3.2에서 실제로 구독할 수 있는 신호만 썼습니다(SDK 클래스를 직접 열어 확인).

| 기능 | 기회가 있었다고 보는 조건 (이번 운전 중) | 썼다고 보는 신호 |
|---|---|---|
| 공조 AUTO | 풍량·온도를 손으로 3번 이상 바꿈 | HVAC AUTO 켜짐 |
| 동승석 개별 온도(DUAL) | 조수석에 사람이 앉았고, 온도를 한 번 이상 바꿈 | HVAC DUAL 켜짐 |
| 운전대 열선 | 운전석 시트 열선을 켬 | 운전대 열선 켜짐 |
| 통풍 시트 | 에어컨을 켜고 설정 온도를 21℃ 이하로 둠(시트 열선을 켠 운전은 제외) | 운전석 통풍 켜짐 |
| 오토 라이트 | 전조등을 켰다 껐다 2번 이상 했는데 스위치가 AUTO가 아님 | 전조등 스위치 AUTOMATIC |
| 크루즈 컨트롤 | 한 번에 20분 이상 운전 | 크루즈 ACTIVATED (ENABLED는 대기 상태라 제외, 에뮬레이터에서 확인) |

- 크루즈 조건은 원래 "고속도로 20분"이었습니다. 차속은 Pleos SDK에 없고 Virtual Console에 차속 카드도 없어서, 첫 버전은 연속 주행 시간만 봅니다(한계로 기록).
- 시트 메모리는 원 아이디어에 있었지만 SDK에 메모리 사용을 알리는 구독 신호가 없어(설정 `selectSeatMemory`만 있음) 뺐습니다.

## 구성 단위

| 단위 | 하는 일 | 의존 |
|---|---|---|
| `DriveStats` | 한 번의 운전 동안 신호를 세는 값 묶음 | 없음(순수 Kotlin) |
| `Feature` | 기능 6개: 이름, 안내 문장, 기회 조건, 사용 조건 | `DriveStats` |
| `Coach` | 운전 끝에 무엇을 알릴지, 무엇이 새로 익힘인지 정함 | `Feature`, 진행 기록 |
| `CarWatcher` | Pleos Vehicle SDK 구독 → `DriveStats` 갱신, 운전 시작·끝 알림 | Pleos Vehicle SDK |
| `WatchService` | 포그라운드 서비스. CarWatcher·TTS·알림·저장을 묶음 | 위 전부, Pleos TTS |
| `Progress` | 기능별 알려 준 횟수와 익힘 여부, 마지막 결과 저장 | SharedPreferences |
| `MainActivity` | 마지막 안내 카드와 기능 6개 상태 목록 | `Progress` |
| `BootReceiver` | 부팅 후 서비스 시작 | `WatchService` |

데이터 흐름: 차 신호 → CarWatcher → DriveStats → (P 전환) → Coach → Progress 저장 → TTS·알림 → 화면.

## 오류 처리

- SDK 구독이 실패하면(`onFailed`) 그 신호는 없는 것으로 봅니다. 그 신호에 기대는 기능은 기회 조건이 성립하지 않아 알리지 않습니다. 틀린 안내보다 침묵이 낫습니다.
- TTS 초기화나 발화가 실패해도 알림과 카드는 그대로 남습니다.
- 운전 중 앱이 죽었다가 다시 뜨면 그 운전 기록은 버립니다(다음 운전부터 다시 셉니다).

## 테스트

- `DriveStats`·`Feature`·`Coach`는 안드로이드 없이 JUnit으로 검증합니다.
- 차 연동은 Pleos 에뮬레이터와 Virtual Console로 확인합니다(기어 D → 공조 조작 → P).
